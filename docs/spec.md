# PAシートメーカー 要件定義 v1

## 1. 目的

会場ごとに異なるPAシート（セッティング図・セットリスト）のPDFをブラウザに取り込み、バンド名・曲順などのテキストと、マイクやアンプを表す図形を配置して書き出す。フォーマットは会場依存のため決め打ちのフィールドは持たず、任意位置に自由配置する。

現状の記入手段は、Word で図形を描く・手書きしてスキャンする・机の上で撮影する、が混在している。この最後の経路を消すのが実質的な目標。したがって、部員が触って数秒で分かるUIであることを機能の多さより優先する。

## 2. 実物から確認した前提

サンプル（Artist Plot / MANHOLE SET LIST / PA要望紙）を見て確認した事実。以下の設計判断の根拠になっている。

- **同じフォームが繰り返し使われる。** Artist Plot は4/8と12/24で同一、MANHOLE は2月の2日分で同一。「会場ごとに違う」が、会場の数自体は少ない。→ 複製機能の価値が高い（F-6）
- **書き込みの大半はテキスト。** 図形が要るのはセッティング図の枠だけで、ページの1/4程度。曲順表・ヘッダ・持込機材欄は全部テキスト。→ 体感速度を決めるのは図形パレットではなくテキスト入力の効率（F-3）
- **使われている記号は4種類だけ。** 矩形＋ラベル（アンプ、パート）、○囲み＋ラベル（メンバー）、マイク記号、線。モニターのくさび、DI、ブーム/ストレートの区別は一つも出てこない。タムは円で描かず「2タム」「1T1F」とテキストで書かれることが多い
- **「箱の中に文字が入っている」形が支配的。** → 図形とテキストを別オブジェクトにせず、ラベル付き図形を基本プリミティブにする（F-4）
- **Artist Plot のセッティング枠内の文字は8pt相当。** → ズームは必須要件

## 3. スコープ

**やること**：PDFの取り込み、テキスト配置、図形配置、線、保存・再開、PDF/画像の書き出し

**やらないこと**：フリーハンド描画、タッチ・ペン入力への対応、入力チャンネル数やAUX系統の検証、必要機材の集計、複数バンド分の一括管理、提出状況の管理、サーバー側の処理一切

## 4. 制約

- **PCのマウス・キーボード操作を前提とする。** タブレットやペン入力は想定しない
- 完全クライアントサイド。PDFをサーバーに送信しない
- 静的ホスティング（GitHub Pages 等）、ログインなし。URL共有で部内に配布
- 会場ではネットワークが不安定な可能性があるため、初回読み込み後はオフラインで動作すること（Service Worker でキャッシュ）
- 保存データは端末ローカルにのみ残る。他人に渡す手段は書き出したPDF/画像

## 5. 機能要件

### F-1 PDFインポート
- ファイル選択とドラッグ&ドロップ
- 複数ページ対応（ページ送り、サムネイル一覧）。想定はA4、1〜10ページ
- pdf.js でcanvasにレンダリング。devicePixelRatio を考慮し高解像度画面でぼやけないこと

### F-2 表示
- ズーム（幅フィット / 100% / ホイール）、パン
- 注釈レイヤーの表示・非表示切替（元のPDFだけを確認できる）

### F-3 テキスト
- クリックで配置、インライン編集。サイズ・色・移動・削除
- **連続入力**：Enterで確定すると、次の行の位置に入力枠が自動で降りる。行間は最初の2行の差分から決定し、以降は自動。フォームの解析はしない
- 連続入力で置いた各行は独立したオブジェクトとして残り、後から個別にサイズ・位置を変えられる（文字数の多い曲名だけ小さくする、等）
- 対象：曲順表（10〜14行）、メンバー表、バンド名、出演順、持込機材欄

### F-4 図形
- 基本プリミティブは**ラベル付き図形**。図形とラベルは1オブジェクトとして一緒に動く
- 回転・拡大縮小が必須（向きが毎回変わるため）
- 初期セット：

| 記号 | 用途 | 備考 |
|---|---|---|
| 矩形＋ラベル | アンプ（JC-120, Marshall, Ampeg）、パート | 最頻出 |
| ○囲み＋ラベル | メンバー、パート | |
| マイク記号 | Vo/Choマイク | ○と↑で**1オブジェクト**。分解しない。回転で向きを変える |

- マイク記号は Artist Plot の上向き指定も MANHOLE の横向きも、同じ記号を回転して賄う

### F-5 線
- 始点→終点ドラッグ、水平・垂直スナップ
- 用途はアンプとメンバーを結ぶ線が中心
- 矢印の有無を切り替えられる

### F-6 保存・再開
- IndexedDB に自動保存。**PDF本体（Blob）も保存する**。注釈だけだと再開のたびにPDFを入れ直すことになる
- ドキュメント一覧（会場名・日付で管理）
- **複製**：前回の注釈ごとコピーして、バンド名と曲名だけ差し替える運用を想定。同じフォームが繰り返し使われるため、これが最も頻度の高い操作になる見込み
- 容量が上限に近づいたときの警告と、古いドキュメントの削除UI

### F-7 共通操作
- 選択、移動、削除、undo/redo（最低20段）
- キーボードショートカット（Delete、Ctrl+Z / Ctrl+Y）。PC前提なので入れる

### F-8 書き出し
- **PDF**：注釈レイヤーをラスタライズし pdf-lib で元ページに合成（§7）
- **PNG**：ページ単位
- 印刷はブラウザ標準
- モノクロ印刷を前提に、色に依存しない見た目にする

## 6. データモデル

```json
{
  "id": "uuid",
  "name": "MANHOLE 2026-02-09",
  "pdfBlobKey": "idb-key",
  "pages": [
    {
      "index": 0,
      "annotations": [
        { "type": "text", "x": 0.42, "y": 0.18, "text": "オンリーワンダー", "size": 14, "color": "#000" },
        { "type": "shape", "kind": "box", "x": 0.3, "y": 0.5, "w": 0.08, "h": 0.04, "rotation": 0, "label": "JC-120" },
        { "type": "shape", "kind": "mic", "x": 0.5, "y": 0.7, "scale": 1.0, "rotation": 0 },
        { "type": "line", "x1": 0.1, "y1": 0.2, "x2": 0.3, "y2": 0.2, "width": 2, "arrow": false }
      ]
    }
  ]
}
```

**座標はページ幅・高さに対する 0〜1 の正規化値で持つこと。** ズーム倍率・画面解像度が変わっても位置がずれず、同じフォームへの複製がそのまま成立する。後から直すのは高くつくので最初に固定する。

図形はSVGパスとして定義し `kind` で参照する。図形の追加が定義ファイルへの追記だけで済む形にしておく。

## 7. 書き出し方式についての判断

pdf-lib の標準フォントには日本語が含まれないため、テキストをそのままPDFに埋め込めない。選択肢は2つ：

1. Noto Sans JP のサブセットを fontkit で埋め込む → ベクタで残るが数MBのダウンロードが発生
2. 注釈レイヤーを画像化して元ページに合成 → フォント不要、実装が単純。注釈部分だけラスタ化される

**方式2を採用する。** 印刷して現場で使う用途では画質は足りる。ラスタ化解像度は元ページの実寸に対して200〜300dpi相当を確保すること。

## 8. 技術構成

- 表示 pdf.js、書き出し pdf-lib、ビルド Vite + TypeScript、保存 IndexedDB、ホスティング GitHub Pages
- 対応ブラウザ：Chrome / Edge 最新
- 入力はマウスイベントのみ。ペン・タッチ固有の処理は実装しない

## 9. 段階リリース

| Phase | 内容 |
|---|---|
| 1 | テキスト（連続入力含む）、図形、線、undo、PDF/PNG書き出し |
| 2 | 複数ページ、保存・再開、ドキュメント一覧、複製 |
| 3 | 図形の調整、オフライン対応 |

Phase 1 の中では、書き出しを先に通しておくこと。ラスタ化した注釈が印刷に耐えるかは実際に1枚刷ってみないと分からず、ここが不足していると解像度の設計をやり直すことになる。
